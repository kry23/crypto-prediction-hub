## Diagnostic journey

### Task 1.5.1 — Short alpha computation (`e27701e`)

**Hypothesis**: maybe short side has signal too; runner.py had `short_alpha = 0.0` hardcoded.

**Fix**: properly compute long/short rankings by `(p_up - 0.5) × |expected_return|` and `(0.5 - p_up) × |expected_return|` separately, with short_alpha = -top_k_alpha(top_short_actual).

**Result**: identical hit rate (56.6%), but **alpha went from -0.47% to +1.62%**. The "negative long alpha" was a measurement artifact — pre-fix code ranked by `abs(expected_return)` only, mixing long and short magnitudes into one bucket. Real long alpha was +0.82% all along.

**Takeaway**: ALWAYS look for measurement bugs before formula bugs. The model already had signal.

### Task 1.5.2 — Per-tilt correlation diagnostic (`ff24784`)

**Hypothesis**: equal weighting assumes equal signal quality; reality is probably unequal.

**Method**: Pearson correlation of each tilt's output with realized 24h return across 1,647 (sym, asof) pairs.

**Findings**:
- `tilt_technical` is the workhorse: +0.18 overall, +0.33 in CHOP, +0.04 in BULL
- `tilt_momentum` regime-flips: +0.19 BULL, **-0.21 CHOP**. Overall ~0 because the two regimes cancel
- `tilt_perp` is mildly anti-predictive: -0.04 overall
- `tilt_volume` is essentially zero: +0.02
- `tilt_sentiment` and `tilt_global` are NaN (caches were empty during the backtest)

**Takeaway**: the static "intuition" weights `[mom 0.20, perp 0.25, vol 0.10, tech 0.15, sent 0.15, global 0.15]` were far from optimal. Technical was under-weighted at 0.15. Momentum should be sign-flipped in CHOP. Perp should be near-zero. Sentiment/global should be zero until caches populate.

### Task 1.5.5 — Data-driven weight rebalancing (`93b87a1`)

**Implementation**: new per-regime weights derived from Task 1.5.2 correlations, plus a CHOP-momentum sign flip.

```python
DEFAULT_REGIME_WEIGHTS = {
    "BULL": {"momentum": 0.35, "perp": 0.05, "volume": 0.05, "technical": 0.15,
             "sentiment": 0.00, "global": 0.00},
    "CHOP": {"momentum": 0.20, "perp": 0.05, "volume": 0.05, "technical": 0.50,
             "sentiment": 0.00, "global": 0.00},
    "BEAR": {"momentum": 0.10, "perp": 0.10, "volume": 0.05, "technical": 0.50,
             "sentiment": 0.00, "global": 0.00},
}
MOMENTUM_FLIP_BY_REGIME = {"BULL": 1.0, "CHOP": -1.0, "BEAR": 1.0}
```

`compute_direction_raw_for_regime` normalizes weights to sum-to-1 internally (sentiment/global at 0 means active weight total is 0.60 in BULL, 0.80 in CHOP/BEAR — normalized at runtime).

**Result on 30-sym × 60-day**: hit rate 56.6% → **62.7%**, combined alpha +1.62% → **+3.10%**. All targets passed.

## Why the heuristic works now

The previous heuristic's failure modes were:

1. **Long alpha measurement was broken** (Task 1.5.1 fix)
2. **Tilt weights were intuition-based, not data-derived** (Tasks 1.5.2 + 1.5.5 fix)
3. **CHOP momentum was contradicting itself** by not sign-flipping (Task 1.5.5 fix)

These three fixes unlock the model. The underlying tilts always had signal — `tilt_technical` alone has +0.33 correlation in CHOP, which is large for a single feature in noisy crypto data. The issue was always the *combination*, not the *signals*.
